# Confucius4-R2T2 词级时间戳：完整实现方案分析

> 结论先行：R2T2 的时间戳能力**不在 R2T2 权重本身**，而在配套的独立强制对齐模型 **Qwen3-ForcedAligner-0.6B** 里。用户提到的「强制时间对齐数据 + Token 级音频分割」是官方训练 R2T2 与 ForcedAligner 共同依赖的**底料机制**，不是 R2T2 直接吐出时间戳 token。audio.cpp 的 `qwen3_asr` family **已经完整实现了这套双模型管线**，而 `confucius4_r2t2` 移植时没接 —— 所以完整实现 = 把 qwen3_asr 的 forced-aligner 管线照搬到 confucius4_r2t2，暴露通过 `--words-out` / `/v1/audio/transcriptions` 的 `words` 字段 / C API。

---

## 1. 澄清一个关键事实：R2T2 时间戳「能力在哪」

用户提问的立论「模型训练时用了强制时间对齐数据 + Token 级音频分割，官方 vLLM API 留有 `return_time_stamps`（默认 False）——能力在权重里，接口没默认打开」，方向基本正确，但要精确到**哪份权重**：

### 1.1 官方技术声明（已验证，网易有道官方发文 + Qwen3-ASR 技术报告）

| 来源 | 原文关键句 |
|---|---|
| 有道官方 R2T2 发布文 | 「训练过程中，团队引入了包括：Stable-prefix data、**Forced time-alignment data**、**Token-level audio segmentation** 在内的数据构造方法」 |
| Qwen3-ASR 技术报告 (arXiv 2601.21337) | 「Qwen3-ForcedAligner-0.6B employs a pretrained AuT encoder…The transcript is reformatted by appending start and end timestamp labels…each timestamp label is replaced with a special token [time]…timestamps discretized into indices by dividing by the **80ms frame duration** of the AuT encoder output」 |

### 1.2 机制拆解（图为「先图后解释」）

```
                    ┌──────────────────────────── 音频 ────────────────────────────┐
                    │                                                             │
       R2T2 (1.7B) 流式转写            Qwen3-ForcedAligner-0.6B (非自回归对齐)       │
  audio → AuT → 稳定前缀 → 文本   audio → AuT(80ms/帧 token) → 时间戳索引×80ms     │
     输出 only 文本(无时间戳)        + 文本每个词/字后插 <time> slot                │
                    └────────────── 文本+语言 ──────────────────→ 词级 [start,end]  │
```

- **R2T2 输出是 `How <wait> are <wait> you?`**（`<wait>` 是 Stable Prefix 的等待标记，官方架构图）。它负责「说得准 + 只增不改」，**不输出时间戳 token**。
- **时间戳由 Qwen3-ForcedAligner-0.6B 给出**：AuT 编码器把音频切成 80ms 一帧的 token 流；文本每个词/字后插两个 `<time>` 占位；模型**非自回归**一次预测所有 slot 的时间戳索引，`时间 = 索引 × 80ms`（`timestamp_segment_time=80`，最大 3750 类 = 上限 300s）。
- 官方 vLLM 的 `return_time_stamps`（默认 False）只是**让 vLLM 在转录后自动调一次 ForcedAligner**。能力不在 R2T2 权重，**在 ForcedAligner 权重**；音频的「Token 级分割」是二者共用的 80ms AuT 帧底料。

> ⚠️ 这一条与「能力在 R2T2 权重里」的表述**不同**，是本次分析最重要的事实修正：**纯靠 R2T2 单模型拿不到时间戳**，必须引入 ForcedAligner。

### 2.2 qwen3_asr family —— 参考实现已完整

`src/models/qwen3_asr/session.cpp` 已实现**完整双模型时间戳管线**（本次方案照抄对象）：

## 3. 实现方案

### 3.1 方案 A（推荐）：复用 Qwen3-ForcedAligner-0.6B，照搬 qwen3_asr 管线

**核心思路**：R2T2 负责转录，ForcedAligner-0.6B 负责对齐（ForcedAligner 有自己独立的 AuT encoder + Qwen3-0.6B + 时间戳预测层，接受「原始音频 + 文本」，**与转录模型解耦**，天然可配 R2T2）。

改动清单（估量）：

| # | 文件 | 改动 |
|---|---|---|
| 1 | `src/community_models/confucius4_r2t2/session.{h,cpp}` | 构造函数新增 `forced_aligner_model_path` 会话选项 → 构造 `qwen3_forced_aligner::Qwen3ForcedAlignerSession` 子会话（类型与 R2T2 无关，只吃 `Qwen3ASRAssets`，故需用它自己的 loader 加载 `Qwen3-ForcedAligner-0.6B` 目录）|
| 2 | `session.cpp run_single` | 仿 qwen3_asr：`parse_asr_output` 得 text+language 后，`return_timestamps` 且语言可对齐 → `align_request = {audio, Transcript{text, language}}` → `aligner.run()` → 填 `result.word_timestamps` |
| 3 | `model_specs/confucius4_r2t2.json` | ① request 加 `return_timestamps`(bool, 默认 false)、`clamp_timestamps_to_audio`；② session 加 `confucius4_r2t2.forced_aligner_model_path`；③ `capabilities.asr` 加 `"word_timestamps"`（使 `supports_timestamps=true`）|
| 4 | `session.cpp` 白名单 | 放行新增的两个 session 选项（现有 unknown-option 校验 session.cpp:137-154）|
| 5 | CLI/文档 | `--words-out` 对 R2T2 生效；更正 r2t2.md「Not supported」|

**关键风险（必须先实测验证，勿推导当结论）**：

| 风险 | 说明 | 缓解 |
|---|---|---|
| 语言覆盖不匹配 | aligner 只支持 **11 语言**（zh/en/yue/fr/de/it/ja/ko/pt/ru/es），R2T2 支持 **30 语言**。R2T2 转出的 Thai/Vietnamese 等，aligner 分词+对齐质量无保证 | ① 文档明示仅 11 语言有保证；② `has_alignable_words` 对不支持语言的分词已存在（按空格/字符），可加显式语言白名单告警 |
| 长音频切块 | ForcedAligner 上限 300s（3750 类），与 R2T2 的 30s offline 块不冲突；但要像 qwen3_asr 那样**先切块转录、逐块对齐、再归位**，不能对整段一次对齐 | 复用 `append_chunk_word_timestamps` |
| 需要额外权重 | 本机尚无 `Qwen3-ForcedAligner-0.6B` 与 `Qwen3-ASR`（只有 R2T2/hainanji/whisper）；silero_vad 已就位 | 用 `tools/model_manager_v2.py install qwen3_forced_aligner_0_6b_q8_0`（走 hf-mirror/代理）|
| R2T2 的 `<asr_text>` 语言标签 | 自动语言模式下 R2T2 输出 `language X<asr_text>text`，需解析出 X 才能传给 aligner（R2T2 已有 `parse_language_output`）| 复用现有解析，强制语言时直接用 |

### 3.2 方案 B（探索，且与官方不一致，不建议优先）：R2T2 直接出时间戳

用户原立论隐含「R2T2 权重能直接出时间戳」。依据官方报告，R2T2 是**流式自回归解码**，时序用 `(token 位置 × chunk)` 无法保证词级精度，官方**没有**让 R2T2 直接输出词时间戳的接口（只有 `<wait>` 稳定前缀标记）。这条路＝需要重新微调 R2T2 增补 timestamp 输出头，**超出本任务「移植/接线」范畴，且无官方权重支撑**。仅作记录，不推荐。

### 3.3 方案 C（备选）：独立 run `align` 任务，不进 R2T2

不侵入 confucius4_r2t2，让用户**先 R2T2 转录 → 再单独跑 `--task align --family qwen3_forced_aligner`** 两次调用拼时间戳。零改动，但**不是端到端**、多语言/长音频对齐归位要用户自行处理。适合「今天就要用」，不适合「R2T2 自身具备时间戳」。

### 6.4 架构关键结论：R2T2 与 aligner 需串行加载
- R2T2 Q8_0 推理峰值显存约 **9–10GB**（09-23 实测），aligner 需 **1.6–3.1GB**，两者之和 > 12GB（RTX 5070 Ti 12GB）。
- **同一进程内不可同时驻留**；方案 A 的「先 R2T2 转录 → 释放 → 再 aligner 对齐」天然串行，资源上完全可行。
- 备选：若需同卡并行，aligner 可退到 `--backend cpu`（显存归零、仅占 ~1GB 内存），代价是速度下降。
