# audio.cpp 选项透传缺陷 —— 核实与「同类未串联」串联分析（2026-09-21）

> 对 `D:\新建文件夹\vlc_plugin\docs\audio_cpp_跳转转录_重分析_选项透传缺陷_20260920.md` 的逐条核实，并追加「是否还有同类问题未串联」的排查结果。
> 本次核实 = **源码逐行核对 + 前几轮实测交叉印证**，非仅推导。

## 0. 一句话结论

**问题确实存在，文档核心结论成立**；但**根因归因有两处需要修正/补强**（对照模型并非「都双键容错」、漏了「whisper 不校验 request 选项」这个关键机理），且**同类透传断链不止一处，还有额外 4 类未串联**（vad_model_path 作用域错位 / HTTP 顶层字段前缀不一致 / task·timestamps 顶层无特判 / streaming 分支同失效）。

## 1. 问题是否存在 —— 核实：**存在，成立**

复用决定性判据 `max_tokens`（硬截断、与模型语义无关）：

| 变体 | 结果 | 核实 |
|---|---|---|
| 裸名 `--request-option max_tokens=8` | 与 CTRL 相同（未截断） | 成立 |
| 前缀 `--request-option whisper.max_tokens=8` | 截断生效 | 成立 |

**链路彻底核对**（皆实读代码）：

1. **spec 声明裸名**：`model_specs/whisper.json` `options.request` 数组全部为裸名
   （`language`/`max_tokens`/`task`/`timestamps`/`beam_size`/`clip_offset_seconds`/`audio_chunk_mode`/`vad_model_path`）→ `contract.request_option_keys` = 裸名集合。
2. **CLI 逐字写入**：`app/cli/request.cpp:335`
   `request.options = collect_key_value_args(argc, argv, "--request-option")` —— 用户输什么 key 就存什么 key，**无任何前缀规范化**。
3. **session 只读前缀且无裸名 fallback**：`src/models/whisper/session.cpp`
   - L35 `whisper.language`、L43 `whisper.max_tokens`、L51 `whisper.task`、L59 `whisper.timestamps`、
     L70 `whisper.clip_timestamps`、L82 `whisper.clip_offset_seconds`、L92 `whisper.beam_size`、
     L122 `whisper.audio_chunk_mode`、L106 `whisper.cross_kv_precision`、L265 `whisper.vad_model_path`
   - **全部** `options.find("whisper.<name>")`，无一 `{"裸名","whisper.名"}` 双键容错。
4. service 层对 `request.options` **不做前缀重映射**（`app/server/runtime.cpp` 综述确认）。

→ 正常路径（按 spec/文档传裸名）下，whisper 所有 request 选项静默失效。**文档核心结论正确。**

## 2. 根因归因 —— 需修正两处

### 2.1 「对照模型都用双键容错」表述不准确（实证）

实际对照（已实读）：

| 模型 | 读法 | 例 |
|---|---|---|
| canary_asr | **裸名单键** | `session.cpp:44 runtime::find_option(request.options, {"language"})` |
| minimax_h3 | 双键容错 | `{"sampler","minimax_h3.sampler"}` |
| auk / parakeet_tdt / zipvoice | 双键或裸名 | （zipvoice 双键） |
| **whisper** | **只读 `whisper.` 前缀、无裸名 fallback** | 上表全列 |

→ **「read request 选项 = 裸名」才是主流共识**（canary 裸名单键、minimax 双键都包含裸名）；whisper 是**唯一只读带前缀、无裸名路径**的模型。文档「其他模型都用 find_option 双键容错」的类比不准，但**结论方向（whisper 独树一帜、应回退到裸名或双键）正确**。

### 2.2 文档漏掉的关键机理：whisper 根本不校验 request 选项

`WhisperASRSession::run()/prepare()` **未调用 `validate_spec_backed_request_options`**（`spec_backed_model.h:60`）。该校验会按 `contract.request_option_keys`（裸名）拒绝不在白名单的键。

- 后果：带前缀 `whisper.xxx` 的键**不会被 spec 校验拒绝**，能原样到达 session → 这是「CLI/HTTP 传 `whisper.xxx` 能生效、但按 spec 传裸名却失效」的**真正不对称性来源**。
- 反例（会校验的模型）：canary 在 `run()` L40 调 `validate_spec_backed_request_options`，若传带前缀 key 会被**直接抛异常拒绝**——所以「带前缀能过」只对 whisper 成立。

> 这一机理文档未点出，但它解释了为何这个 bug 在 whisper 上表现为「静默失效」而非「报错」，也解释了为什么其他模型（有校验 + 读裸名）不受此坑影响。

**修正后的根因表述**：whisper 是「**只读带前缀键 + 不校验 request 选项**」的组合，导致前缀键可静默穿透、裸名键被静默忽略——规范（裸名）与读取（前缀）双向失配，且无任何护栏暴露。

## 4. ★ 同类未串联问题（本次新增排查，文档未覆盖）

同一根因（whisper 前缀读取 vs spec/入口裸名）的**其他断裂点**，共 4 类：

| # | 断裂点 | 位置 | 表现 / 影响 |
|---|---|---|---|
| A | **vad_model_path 双重失配（作用域+前缀）** | `session.cpp:265` 用 `find_option(this->options().options, {"whisper.vad_model_path"})` | ①读的是 **session 作用域** options，而 spec 把它声明在 **request 作用域裸名**、`session` 数组为空（`whisper.json` `options.request` 有 `vad_model_path`、`options.session` 为 `[]`）→ 即便用户按 spec 传 request 裸名，构造器也读不到；②前缀也不匹配。**最隐蔽的一处**，仅 vad 切分模式受影响 |
| B | **HTTP 顶层字段 vs 前缀不一致** | `runtime.cpp:961` 顶层 `language` 写**裸名**；`runtime.cpp:976` 顶层 `clip_timestamps` 写**前缀** | 同一入口两种命名风格并存。顶层 `"language":"ja"` 落到裸名 → whisper 读 `whisper.language` 恒 `en`（被海南鸡掩盖）。若顶层 `clip_timestamps` 特判没有，则也读不到 |
| C | **HTTP 顶层 task / timestamps 无特判** | `build_openai_transcription_request` 只对 `clip_timestamps` 特判；`task`/`timestamps` 顶层字段不会被解析进前缀键 | 用户传顶层 `"task":"translate"` 或 `"timestamps":true` → 写入 request.options 裸名或直接丢弃 → whisper 恒 `transcribe`/`false`。**文档只列了 clip_offset，未扩展列全** |
| D | **streaming 分支同样失效** | `session.cpp:561-571`（`process_one_stream_chunk`）用同一批 `whisper.<name>` 读取 | streaming 模式下所有 request 选项同样恒默认（language/max_len/translate/timestamps/beam/clip_offset 全空）。**文档只分析 offline `run()`，未提 streaming** |

> 说明：A 影响面最小（仅 `audio_chunk_mode=vad` 时），但它是唯一一个「作用域也错位」的——修复时不能只换前缀，还要把读取目标从 session options 纠正到 request options（或按框架约定改 spec 声明位置）。

## 5. 修复建议（收敛到单一根因，一次改齐）

在 `src/models/whisper/session.cpp` 统一「读 request 裸名，或双键（裸名优先 + 前缀兜底）」，一次性覆盖 7 处 offline 读取 + 5 处 streaming 读取 + 构造器：

1. L35/L43/L51/L59/L70+L82/L92/L122 → 裸名（`language`/`max_tokens`/`task`/`timestamps`/`clip_timestamps`+`clip_offset_seconds`/`beam_size`/`audio_chunk_mode`）。
2. L106 `whisper.cross_kv_precision` → 裸名或移除（spec 未声明，属死代码）。
3. **L265 构造器 `vad_model_path`**：改成从 **request 作用域**读裸名 `vad_model_path`（或将 spec 把该键移到 session 作用域并带前缀，二选一，需与框架约定对齐——推荐移 spec 声明到 session 作用域，避开「session 里硬取 request 键」的越界）。
4. 各读取点若保留向后兼容，用 `find_option(options, {"name","whisper.name"})` 双键。

修复后重编（`-Preset windows-cpu-release -Target audiocpp_cli -ModelSet custom -Models whisper`）并实测：
- `--request-option max_tokens=8` 直接截断（不再需要前缀）。
- `--request-option clip_timestamps=[9,25] --request-option timestamps=true` 使 prompt 注入起点 token（行为可观测）。
- HTTP：顶层 `"language":"ja"`、`"timestamps":true`、`"task":"translate"` 生效；nested options 裸名生效。

## 6. 结论

- **文档核心判定正确**：R1/R2（及 R3 外部偏移）在正常路径下确因命名断链失效，不能下「无缺失」结论。
- **需修正两处归因**：(a)「其他模型都用双键容错」不准——canary 是裸名单键，read-裸名 才是主流，whisper 只读前缀独树一帜；(b) 漏了「whisper 不调用 request 选项校验」这一使 bug 静默化、且让带前缀键得以穿透的关键机理。
- **新增 4 类同类断链未串联**：A vad_model_path（作用域+前缀双重失配）、B HTTP 顶层 language 裸名 vs clip_timestamps 前缀并存、C HTTP 顶层 task/timestamps 无特判、D streaming 分支同批失效。它们与文档所述问题是**同一个命名契约 bug 的不同出口**，应一次性收敛修复，而非只改 clip_offset 一条线。
