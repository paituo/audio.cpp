# whisper 与其他模型 request 选项处理 机制缺失对比分析（2026-09-21）

> 横向对比 audio.cpp 内各 ASR / 生成模型对 request 选项的处理，定位 whisper 相对他们的**机制缺失**。
> 分两类：**A 类=实现缺口/缺陷（应修）**，**B 类=架构差异（设计选择，非缺陷）**。
> 全部结论基于**源码逐行核对**。

## 0. 对照样本

| 模型 | request 读取风格 | 是否 spec 校验 | normalize/兼容 | 备注 |
|---|---|---|---|---|
| canary_asr | **裸名单键** `{"language"}` | ✅ `run()` L40 | ❌ | |
| moonshine_asr | 裸名 | ✅ 多处 | ❌ | |
| fun_asr_nano | 裸名 `{"language"}`/`{"enable_itn"}`/`{"max_tokens"}` | ✅ `validate_request_options` L240 | ❌ | |

| parakeet_tdt | request 裸名 `{"max_tokens"}`；session 前缀 `parakeet_tdt.*` | ✅ | ✅ `normalize_request_options`（版本别名+老 contract 容错） | **机制最全** |

## A 类：实现缺口 / 缺陷（应修）

### A1. request 作用域命名断链（核心，上篇已立证）
**其他模型全部「request 读裸名」**（canary/moonshine/fun/qwen3/parakeet request 侧），唯 whisper 用 `whisper.<name>` 前缀读 request 选项且**无裸名 fallback** → 与 spec（裸名声明）、CLI（逐字写入）、HTTP（裸名/特判混用）三方失配。**全线静默失效**。

落点：`session.cpp` L35/L43/L51/L59/L70/L82/L92/L122/L106/L265。

### A2. 完全缺失「request 选项 spec 校验」（静默吞错 + 让前缀键穿透）
- parakeet_tdt：`normalize_request_options` 内调 `validate_spec_backed_request_options(...)`（`session.cpp:90`）→ 未知 request 键**抛异常**。
- canary/moonshine/fun_asr_nano/auk：都在 `run()` 调该校验。
- **whisper：`run()`/`prepare()`/streaming 全不调** → 任何笔误的键被静默忽略（排错无提示），且正因不校验，带 `whisper.` 前缀的键能**不被拒绝地穿透**到 session —— 这正是「CLI/HTTP 用前缀能生效」的机制性来源。**是一个护栏缺失**。

### A3. 完全缺失「request 选项版本兼容迁移」（apply_option_v1_compatibility）
- 框架提供 `apply_option_v1_compatibility(...)`（`spec_backed_model.h:87`），parakeet_tdt 用它把老字段名（`audio_chunk_seconds`/`audio_chunk_duration_seconds`/`audio_chunk_duration`）一键迁移到 `audio_chunk_duration_sec`。
- 框架 `parse_audio_chunk_seconds_override`（`chunking.cpp:186`）也内建 **4 个别名**兜底。
- **whisper 未用**——若未来/现有别名有出入，新名读不到且无迁移。

### A4. 脱离框架统一 chunking 机制（私有切分，功能缩水）
- 其他 ASR（canary/parakeet/qwen3/fun_asr_nano/niagara）一律用 `engine::audio::parse_audio_chunk_mode(request.options)` + `parse_audio_chunk_seconds_override(...)`，支持 **auto/fixed/quiet_energy/vad/none** 五种模式 + chunk 时长别名。
- **whisper 用自己的私有 `chunk_mode_from_options`**（`session.cpp` L119-125）：
  - 只读 `whisper.audio_chunk_mode`（前缀问题叠加）；
  - **只支持 quiet_energy / vad**，**缺 fixed / auto / none** 三种框架统一模式；
  - **缺 chunk 时长覆盖解析**（`audio_chunk_duration_sec` 等别名），无法调窗长。

### A5. vad_model_path 作用域错位（构造器读 session options，spec 却声明在 request）
- 构造器 `session.cpp:265`：`find_option(this->options().options, {"whisper.vad_model_path"})` —— 读 **session 作用域** options；
- 但 `whisper.json` 把 `vad_model_path` 声明在 **request 作用域（裸名）**、`options.session` 为空 `[]`。
- → 无论如何传都读不到：按 request 裸名传 → 构造器不看 request；按 session 传 → spec session 无此键、且又要前缀。**双重失配**（与上篇 A 项一致）。
- 对照：qwen3_asr 构造器 `qwen3_asr.vad_model_path`（`qwen3_asr/vad` 被 request 引用，但 qwen3 的 vad 走 **session 作用域带前缀** 且 spec 同步声明）——qwen3 前缀与 spec 作用域**一致**，whisper 前后**自相矛盾**。

### A6. 幽灵键 `clip_timestamps`（spec 未声明，session 却读）
- `whisper.json` request 里**没有** `clip_timestamps`（只有 `clip_offset_seconds`），但 `clip_offset_from_options`（L71）优先读 `whisper.clip_timestamps`，HTTP 层 `runtime.cpp:976` 也写 `whisper.clip_timestamps`。
- → 该键既不在 request_option_keys，也无法被 A2 的校验认可（若补了校验需解决）。属「spec 契约与实际实现不一致」的幽灵键。

## B 类：架构差异（设计选择，非缺陷，仅供理解）

### B1. 无「强制对齐器」精修词级时间戳
- **qwen3_asr**：`return_timestamps` 时调用 `qwen3_forced_aligner` 子模型做整段 CTC 强制对齐，产出高质量词时间戳，支持 `clamp_timestamps_to_audio`（`session.cpp` L508-525）。
- **whisper**：词/段时间戳来自解码器 `<|timestamp|>` token，是模型自估，**无后置精修**。这是 Whisper 架构的固有做法（faster-whisper 亦同），非缺陷，但与 qwen3 存在精度/机制差异。

### B2. 无「上下文/session 级推理能力」（LLM-ASR 差异）
- qwen3 是 LLM-ASR，有 thinker/reasoning、`preserve_punctuation`、能按 instruction 改写；whisper 是 Encoder-Decoder 专用 ASR。能力取向不同，非缺失。

### B3. 无 `enable_itn / pnc` 等后处理
- fun_asr_nano 有 `enable_itn`，canary 有 `pnc`（标点/逆文本正则化开关）。whisper 无这些开关——属模型能力差异，非断链类缺陷。

## 修复优先级建议

| 优先级 | 项 | 理由 |
|---|---|---|
| P0 | A1 request 命名断链 | R1/R2/R3 全部依赖，核心 bug |
| P0 | A5 vad_model_path 作用域 | 双重失配，最隐蔽 |
| P1 | A2 补 spec 校验 | 恢复护栏，暴露未知键（修 A1 后前缀键不再穿透，校验可安全启用） |
| P1 | A4 接入框架 chunking | fixed/auto/none + 时长别名，功能补齐且与其他 ASR 统一 |
| P2 | A6 幽灵键 clip_timestamps | 补 spec 声明，或并入 A1 归一化 |
| P2 | A3 版本兼容迁移 | 长期健壮性 |

修复统一落点仍是 `src/models/whisper/session.cpp` 的 `*_from_options` / 构造器：**改读裸名（或双键优先裸名）+ 补校验 + 接入框架 chunking**，可一次收敛 A1/A2/A4/A6；A5 需另把读取目标指向 request 作用域。
