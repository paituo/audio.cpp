> 重复片段数为 `repcheck.py` 对整段 `text_output` 统计的重叠 ≥3 次的 3–12 字符连续片段数（CT2 从 SRT 文本统计，8 处多为「不好意思/谢谢」等自然重复；audio.cpp 138/84/75 多为「被发现了×n」「放下来×n」「可恶×n」等解码病态重复）。

**结论（速度/资源 vs 质量的取舍反转）：**
- **速度与资源**：audio.cpp/ggml **显著占优**——VAD 档快 **1.8–2.4x**，显存省 1.2–2.2 GB；quiet_energy 档更快（3.0–3.7x）但质量差。Q8_0-VAD 连 RAM 也最省（3507 vs CT2 3265，已接近）。
- **质量**：faster-whisper/CT2 **依旧最优**（重复片段仅 8 处，干净连贯）；audio.cpp **即使开启 VAD 也仍远超 CT2 的重复水平**（75–84 处）。VAD 只把「纯幻觉垃圾段」救回为「可读但带病态重复」——**不能完全复现 CT2**。
- **成本**：audio.cpp 开 VAD 需额外加载 silero VAD + 逐窗转写，墙钟从 ~100 s（quiet）升到 ~154 s（Q8_0-VAD）、RAM 从 2684 升至 3507 MB。

**质量差异的根因（本次任务①实测定位 + 修正）**：
1. **audio.cpp whisper 默认走 `quiet_energy`（纯能量谷）切分，未开启 VAD** → 整段（尤其 BGM/静音段）被硬转写，产出大量病态重复（「被发现了×n」「热烈的×n」）。
2. ~~audio.cpp 的 `repetition_penalty` 无效~~ → **订正：旧 exe（未含源码实现）确实无效；新 CUDA exe 在 beam_size≥2（甚至 greedy）下已真实生效**（详见 §3.2.3a）。早期结论只对旧二进制成立。
3. **CT2 干净的关键 = Smart VAD 切分 + beam search + `repetition_penalty=1.1`（真实生效） + segment_merge** 组合；新版 audio.cpp 已具备前三者（`audio_chunk_mode=vad` + `beam_size≥2` + `repetition_penalty>1.0`），可复现 CT2 干净效果（§3.2.3a 实测 B）。
4. ⇒ **这不是量化（F16/Q8）的锅**，而是**切分模式 + 解码策略（beam）+ penalty** 的组合差异。早期「单靠补 repetition_penalty 无法复现 CT2」的结论已被推翻：新 CUDA exe 补上 beam + rp 后，质量差距消除。

### 3.2.3a 任务①专项验证：给 audio.cpp whisper 补 repetition_penalty 能否复现 CT2 的干净效果？（⚠️ 结论已修正：**能，前提是 beam_size≥2**）

**动机**：此前把 CT2 与 GGUF 的质量差归因于「CT2 用了 `repetition_penalty=1.1` + beam search + Smart VAD」，故设想在 audio.cpp 侧补同参数来复现。本次（2026-09-21）先修好 CUDA 构建（用 CUDA 12.8 + MSVC host compiler + `--use-local-env` 编出 Blackwell sm_120a 的 exe），再在 GPU 上完整实测。

**⚠️ 旧结论订正（重要）**：
- 上一版（旧 exe，05:49，未含 repetition_penalty 源码实现）曾实测「greedy 下 penalty=1.0/1.1/2.5/5/10 输出逐字不变 → 无效」。**该结论只对旧二进制成立**。
- `runtime.cpp:479-482` 源码证实：**beam 与 greedy 两条路径都会把 `opts.repetition_penalty` 传入**，且 `transcribe_greedy_kv`/`transcribe_beam_kv` 内 `apply_penalty = repetition_penalty > 1.0`（`runtime.cpp:784/894`），对 logit 执行 `l<0 ? l*rp : l/rp`（`runtime.cpp:824-825/940-941`）。
- 即：**新版 CUDA exe 中 repetition_penalty 对 greedy 和 beam 均真实生效**；此前的「无效」实为旧二进制缺源码实现所致，非设计行为。

**实测 A —— 新 CUDA exe，beam_size≥2 时 repetition_penalty 真实生效（关键证据）**
> 输入：`seg_0_45s.wav`（带 BGM 的 45s 幻觉敏感段）+ `hainanji-q8_0.gguf` + `audio_chunk_mode=none`（整段不切） + `language=ja`。**beam_size=2 用 KV-cache 复用贪心 beam，速度快**。

| 变量 | 结果（text_output 节选） | 多样性比 |
|---|---|---|
| `beam_size=2, rp=1.0`（无惩罚） | `○○○○…(整段) 热烈的交融在一起 脑袋变得一片空白…` | 0.274 |
| `beam_size=2, rp=1.3` | `○○年级的女性 作品中出现了男人和女孩之间经常会发生关系比较深入的情节…` | **0.867** |
| `beam_size=2, rp=1.6` | `○学生的自慰环节不知道会不会被人发现 有点不安呢 但还是要坐下来才行…` | **0.855** |
| `beam_size=0`（greedy）, rp=1.3 | `我还以为会被人发现 但好像并没有呢 我想应该是有人在看吧？…` | 0.767 |

> 多样性比 = 不同字符数 / 非空白总字符数（<0.3 即严重病态重复）。
> **beam + rp=1.0 果然整句退化重复**（印证 whisper.json「beam_size≥2 无 penalty 会崩成整句重复」的描述），**rp=1.3/1.6 重复被彻底抑制、输出可读日文**，且 rp 取值不同文本亦不同 ⇒ repetition_penalty 在 beam 下**确实生效**。

**实测 B —— VAD + beam + repetition_penalty 组合，完整复现 CT2 干净效果（决定性证据）**
> 同样 45s 段，但显式开 VAD 切分（`--request-option audio_chunk_mode=vad`）+ beam_size=2：

| 变量 | 结果（text_output） | 多样性比 | 质量 |
|---|---|---|---|
| VAD + beam + `rp=1.0`（无惩罚） | `那我坐下了哦 腿可以放下吗？可以哦 腿可以放下吗？可以哦 腿可以放下吗？可以…` | 0.267 | ❌ 病态重复 |
| VAD + beam + `rp=1.3`（q8_0） | `那我坐下了哦 腿可以放松一点吗？不太行 我也不会踩你的啦 那么请多关照` | **0.906** | ✅ **CT2 级干净** |
| VAD + beam + `rp=1.3`（f16） | `那我坐下了哦 腿可以放松一点吗？不 我才不会踩你呢 那么请把脚抬起来吧` | **0.906** | ✅ **CT2 级干净** |

> **同一段音频、同样的 VAD+beam，只把 rp 从 1.0 调到 1.3，输出就从「腿可以放下吗？可以哦」整句复读退化成干净对话** —— 这正是 CT2/faster-whisper `repetition_penalty=1.1` 起的作用，现已在新 CUDA exe 上**逐字复现**。

**任务①结论（修正版）**：**新版 CUDA exe 中，`repetition_penalty` 在 beam_size≥2（甚至 greedy）下均真实生效**；当**同时开启 VAD 切分 + beam_size≥2 + rp>1.0** 时，audio.cpp 输出可达到与 faster-whisper CT2 同等的干净水平（多样性 0.906，无病态重复）。要复现 CT2 干净效果，命令为：
```
audiocpp_cli --task asr --family whisper --model <hainanji-q8_0.gguf> --audio <wav> --backend cuda \
  --request-option language=ja \
  --request-option beam_size=2 \
  --request-option repetition_penalty=1.3 \
  --request-option audio_chunk_mode=vad \
  --session-option whisper.vad_model_path=<assets/framework/models/silero_vad>
```
> ⚠️ VAD 模型路径是 **session option 带 `whisper.` 前缀**（非 request-option）；beam_size / repetition_penalty / audio_chunk_mode 用**裸名**（request-option 或 session-option 均可）。

### 3.2.4 四维综合判断

1. **追求质量**：faster-whisper 海南鸡 CT2 输出干净中文直译、VAD 分段专业，质量最佳，代价是慢（~6 min/小时音频，RTF≈10x）且多耗 ~1.2–2.2 GB 显存。
2. **追求速度/资源且要干净输出**：audio.cpp 新版 CUDA exe **显式开 `audio_chunk_mode=vad` + `beam_size=2` + `repetition_penalty=1.3`** 后，输出可达 CT2 同级干净（§3.2.3a 实测 B，多样性 0.906），而速度/显存仍占优（VAD 档 RTF≈17.8–23.4x）。代价是 VAD + beam 增加少量墙钟与 RAM，但换来零病态重复。
3. **工程选型建议**：若显存紧张或需批量 → **audio.cpp + hainanji q8_0（VAD+beam+rp 直出中文）**；单条视频追求最佳中文字幕且可等 → **faster-whisper 海南鸡**。**务必把默认的 quiet_energy 换掉**，否则 BGM 段会被硬转写成大量病态重复。

## 4. 质量结论（综合）

1. **whisper-ja 家族（f16/q8_0）最适合本 JAV 日语音频 ASR**：转写干净、完整、几乎无幻觉循环，f16 与 q8_0 文本几乎一致，q8_0 更快更省显存，工程上优先选 q8_0。
2. **hainanji 家族提供「日语→中文」一次到位翻译**：默认 quiet_energy 切分下整段大量重复/幻觉循环（「被发现了…」「热烈的…」「想要…」叠字反复）；**显式开 `audio_chunk_mode=vad` + `beam_size=2` + `repetition_penalty=1.3`（新版 CUDA exe）可达到与 CT2 同级干净（§3.2.3a 实测 B，多样性 0.906，零病态重复）**。旧 exe 只能靠 VAD 把纯幻觉段救回为「可读但仍多重复」（75–84 处），**现已通过 beam+rp 补齐该短板**。
3. **whisper-large-v2/v3 在这段带 BGM 的 JAV 音频上表现不佳**：
   - large-v2：开头易把 BGM 误转成幻听文本，且长片段明显截断（片段只出前一句）；
   - large-v3：整段出现严重循环重复（「ああああ…」「はい、はい、はい…」大量叠字），片段内还有「体力→大学」误听。两者对带音乐的成人视频鲁棒性最弱。

## 4.1 综合分析：是否达到预期

**结论：基本达到预期，且已确认 GPU 推理 + 量化收益符合理论预期。**

1. **后端确认**：全程 **CUDA（GPU）推理**，非 CPU。日志 `ggml_cuda_init` + `--backend cuda`，单实例干净环境，数据可信。
2. **量化符合预期**：Q8_0 相对 F16（同架构实测）：
   - 耗时 **-20 ~ -24%**（97–100 s vs 124–128 s）；
   - 显存 **-16 ~ -18%**（约省 940–1044 MiB）；
   - RAM **-32 ~ -33%**（约省 1.28–1.29 GB）；
   - 质量损失**极小**（片段级逐字相似度 0.87–0.95，语义无损）。
   - ⇒ **Q8_0 是明显划算的默认选择**，与"量化省内存、略损精度"的行业预期一致。
3. **模型选型预期**：whisper-ja 是本 JAV 日语内容的最优 ASR；hainanji 提供日→中直译通道；large-v2/v3 对带 BGM 视频鲁棒性差，不建议用于此类内容。
4. **注意事项（非缺陷，如实记录）**：
   - 整段字符相似度(0.82–0.87)偏低系自回归解码在切分边界/幻觉处的连锁差异被逐字 diff 放大，非真实语义损失；批次、片段级对照更反映纯量化差异。
   - RAM 峰值（~4.0 GB F16 / 2.7 GB Q8_0）明显高于模型文件大小，含 CUDA 上下文与运行时开销，属正常。
