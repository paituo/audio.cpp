# whisper 选项透传缺陷 A1–A6 修复 + 实测验证报告（2026-09-21）

> 针对上两份分析（选项透传缺陷核实、机制缺失对比）中的 A1–A6 实施修复并硬实测验证。
> 修改面：`src/models/whisper/session.cpp` + `model_specs/whisper.json`；重编 `audiocpp_cli`/`audiocpp_server`/`engine_model_whisper`（MSVC 14.51 + ninja，CPU release）。

## 0. 修复总览

| 项 | 问题 | 修法 | 实测证据 |
|---|---|---|---|
| A1 | request 选项只读 `whisper.` 前缀、无裸名 fallback → 按 spec 传裸名全部静默失效 | 新增 `normalize_request_options`（入口剥 `whisper.` 前缀→裸名，向后兼容），`*_from_options` 改读裸名 | CLI 裸名 `max_tokens=8` 截断；裸名 `timestamps=true` 出 segments/words；裸名 `clip_offset_seconds`+`timestamps` 触发 R2 |
| A2 | 缺 spec 校验、静默吞错 | 未引入硬校验：ASR 会收到框架通用键（route/audio_chunk_seconds 等），硬校验会误伤；改为归一化+裸名读取原生消除「合法键失效」 | 所有合法键（裸名或前缀）均能正确读取 |
| A3 | 缺版本兼容/别名迁移 | `chunk_mode_from_options` 委托框架 `parse_audio_chunk_seconds_override`（多别名兜底）+ normalize 迁移 quiet_energy→auto | `audio_chunk_duration_sec=10` 生效 |
| A4 | 私有 chunking 只支持 quiet_energy/vad、缺 fixed/none/auto+时长别名 | 改委托框架 `engine::audio::parse_audio_chunk_mode`，run() 三分支（Vad/Fixed/auto·quiet_energy·none→能量切分） | 40s 音频 fixed+10s → 窗口起点精确 0/160000/320000/480000 |
| A5 | vad_model_path 作用域+前缀双重失配 | spec 把 `vad_model_path` 移入 session 作用域（裸名，框架推导 `whisper.vad_model_path`），构造器读 session 前缀与之匹配（同 qwen3） | vad 模式默认+自定义 session 路径均正常初始化 |
| A6 | 幽灵键 `clip_timestamps`（spec 未声明、session 却读） | spec request 补声明 `clip_timestamps`（裸名） | CLI 裸名 `clip_timestamps=[9,25]` 生效；HTTP 顶层生效 |

## 1. 关键代码改动

### session.cpp
- 新增 `normalize_request_options()`（匿名命名空间）：剥 `whisper.` 前缀、迁移 `audio_chunk_mode=quiet_energy/default→auto`、裸名优先。
- 全部 `*_from_options` 由 `options.find("whisper.<name>")` → `options.find("<name>")`（language/max_tokens/task/timestamps/clip_timestamps/clip_offset_seconds/beam_size/audio_chunk_mode）。
- 新增 `chunk_mode_from_options` 委托框架（返回 `AudioChunkMode`），删除旧私有 string 版本。
- `run()` / `process_one_stream_chunk` 入口先 `normalize_request_options(request.options)`，后续统一用归一化 map。
- 构造器 `vad_model_path` 仍读 session 前缀 `whisper.vad_model_path`（A5 靠 spec 移动匹配）；`cross_kv_precision` 保持 session 前缀（构造器内，与 request 不同路）。
- `whisper_runtime_options_from_options` 保持读 `whisper.cross_kv_precision`（session 作用域）。

### whisper.json（spec）
- request 补 `clip_timestamps`（`[start,end]` string，默认 ""）。
- request 的 `audio_chunk_mode` values 扩为 `auto/fixed/quiet_energy/vad/none`。
- `vad_model_path` 从 request 移到 session（name 为裸名，框架推导 `whisper.vad_model_path`）。

## 3. ★ 实现踩坑（已修复）

首次实现 A4 fixed 切分时，把「none 回退 quiet_energy」的代码误放在 `if/else if/else` **分支之外**，导致每次执行完分支后又**无条件重算并覆盖 `spans`**：
- 编译通过、行为看似正常（A4 首次实测也"过了"），实际 fixed 分支被静默吞掉（start_sample 只落在能量谷间隔，无精确 160000×k）。
- 二次审查发现重复块后删除，重测 start_sample 精确落在 160000×k 才真正确认 fixed 生效。

**教训**：分支外放一段无条件重算=静默覆盖分支结果，必须逐块审 if/else 闭合点 + 用精确数值判据（非"能跑通"）验证分支是否真执行。

## 4. A2 说明与取舍

whisper 是 ASR，`request.options` 会被框架注入通用键（`route`/`audio_chunk_seconds`/`source_audio` 等，见 `app/cli/request.cpp` build_request_from_cli 大量 set_option）。若引入 `validate_spec_backed_request_options`（parakeet/canary 的严格白名单校验），这些框架通用键会被判非法而**拒绝整请求**。因此 A2 不采用硬校验，而以「入口归一化 + 裸名读取」原生消除本次缺陷（合法键不再静默失效、未知键不误伤）。如需后续严格护栏，可仿 parakeet 的 `normalize_request_options`（先归一化白名单键、再校验），属可选增强。
